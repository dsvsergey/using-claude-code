Claude Code для команды

Короткое практическое руководство: как настроить, как не сжигать токены, как хранить знания о проекте локально и как работать так, чтобы результат был предсказуемым.

⚙️ настройка🧠 база знаний💸 токены📐 spec-driven✅ практики

1. Быстрый старт

  1. Установите Claude Code (см. официальную документацию — docs.claude.com).
  2. Откройте терминал в корне репозитория и запустите claude.
  3. Выполните /init — Claude проанализирует код и создаст стартовый CLAUDE.md. Отредактируйте его вручную: убрать воду, добавить то, чего не видно из кода.
  4. Закоммитьте CLAUDE.md, .claude/settings.json и .mcp.json — тогда вся команда стартует с одинаковой конфигурацией.
cd my-repo
claude          # интерактивная сессия
/init           # сгенерировать CLAUDE.md
/status         # проверить модель, аккаунт, настройки

2. CLAUDE.md — память проекта

CLAUDE.md загружается в контекст каждой сессии. Поэтому он должен быть коротким и плотным: каждая строка стоит токенов в каждом запросе.

Где лежит

~/.claude/CLAUDE.mdличные правила для всех проектов
./CLAUDE.mdправила проекта, в git, для всей команды
./CLAUDE.local.mdличные правила для проекта (в .gitignore)
./subdir/CLAUDE.mdподгружается, когда Claude работает в этой папке

Что писать

  • Команды: build, test, lint, запуск одного теста.
  • Архитектурные границы: «UI не ходит напрямую в БД».
  • Конвенции, которые не видны из кода.
  • Ловушки: «миграции только через …», «не трогать legacy/».
  • Ссылки на подробные документы через @docs/file.md вместо копирования текста.

Чего не писать

  • Описание структуры папок, которое Claude и так видит.
  • Общие советы («пиши чистый код»).
  • Секреты, токены, пароли.
Пример CLAUDE.md 
# Project: billing-api

## Commands
- Install: `pnpm i`
- Test all: `pnpm test` · one file: `pnpm vitest run path/to/file.test.ts`
- Lint+types: `pnpm lint && pnpm typecheck` (run before saying "done")

## Architecture
- `src/domain` — pure logic, no IO. `src/infra` — DB/HTTP adapters.
- All DB access via repositories in `src/infra/repos`. Never import prisma elsewhere.

## Conventions
- Errors: return `Result<T, AppError>`, never throw in domain.
- New endpoint = handler + zod schema + test in `tests/api`.

## Gotchas
- Money is integer cents. Never use float.
- `legacy/` is frozen — do not modify.

## More docs
- @docs/architecture.md
- @docs/release-process.md

💡 Совет: во время работы говорите «добавь это в CLAUDE.md», когда Claude ошибся из-за незнания конвенции. Так файл растёт из реальных проблем, а не из выдуманных правил. Раз в месяц чистите его.

3. settings.json и разрешения

~/.claude/settings.jsonпользовательские настройки
.claude/settings.jsonпроектные, в git — общие для команды
.claude/settings.local.jsonличные для проекта, не коммитятся

Разрешения убирают постоянные запросы «Allow?» для безопасных команд и запрещают опасные. Управлять можно командой /permissions или вручную:

{
  "permissions": {
    "allow": [
      "Bash(pnpm test:*)",
      "Bash(pnpm lint:*)",
      "Bash(git status)",
      "Bash(git diff:*)",
      "Bash(git log:*)"
    ],
    "deny": [
      "Read(./.env)",
      "Read(./.env.*)",
      "Read(./secrets/**)",
      "Bash(git push:*)",
      "Bash(rm -rf:*)"
    ]
  }
}

⚠️ Не включайте режим «пропускать все разрешения» на рабочей машине с доступом к прод-секретам. Если нужна полная автономия — запускайте в контейнере / devcontainer.

4. Общая конфигурация команды

Идея: всё, что делает Claude «умным» в вашем проекте, лежит в репозитории и проходит code review, как обычный код.

repo/
├── CLAUDE.md                 # правила проекта
├── .mcp.json                 # общие MCP-серверы (без секретов!)
├── .claude/
│   ├── settings.json         # разрешения, hooks
│   ├── commands/             # собственные /slash-команды команды
│   │   └── review-pr.md
│   ├── agents/               # специализированные subagents
│   │   └── test-writer.md
│   └── skills/               # skills с инструкциями и скриптами
│       └── release/SKILL.md
├── docs/                     # подробная документация, на которую ссылается CLAUDE.md
└── specs/                    # спецификации (Spec Kit)
  • Секреты для MCP — через переменные окружения (${API_KEY} в .mcp.json), а не в файле.
  • Изменения в CLAUDE.md и .claude/ — через PR, как и код.
  • Для набора общих инструментов между репозиториями — оформите plugin и внутренний marketplace (/plugin).

5. Экономия токенов и контекста

Главное правило: контекст — самый дорогой ресурс. Чем он больше и «грязнее», тем дороже и хуже работает модель.

Привычки

  • /clear между независимыми задачами. Одна сессия = одна задача.
  • /compact с подсказкой, что сохранить: /compact оставь план и список изменённых файлов.
  • /context — посмотреть, что занимает контекст (MCP-тулы, файлы памяти и т.д.).
  • Давайте точные пути: @src/billing/invoice.ts вместо «найди, где счета».
  • Большие исследования («пройдись по всему репо») — через subagent: он читает файлы в своём контексте и возвращает только вывод.
  • Отключайте MCP-серверы, которые не нужны в этом проекте — описание каждого тула занимает контекст.
  • Не вставляйте огромные логи — давайте хвост или фильтр (| tail -50, grep ERROR).

Выбор модели

  • /model — переключение. Мощная модель — для планирования и сложных задач, более быстрая/дешёвая — для рутины.
  • Для subagents можно задать отдельную, более дешёвую модель в их frontmatter.

Измерение

  • /cost или /usage — расходы текущей сессии / лимиты.
  • ccusage — анализ локальных логов Claude Code: расходы по дням и сессиям.
  • Statusline (/statusline) — показывать заполненность контекста прямо в терминале.

💡 Локальная база знаний экономит токены не «магически», а потому, что Claude получает маленький точный фрагмент (узел графа, заметку, сигнатуру функции) вместо чтения десятков файлов. Эффект максимален на больших репозиториях и повторяющихся вопросах.

6. Локальная база знаний: тулы

Три разные задачи — три типа инструментов. Не ставьте всё сразу: начните с 1–2 и посмотрите на /context и /cost.

Карта кода (что где лежит и как связано)

graphify

Строит граф знаний (код, документы) в graphify-out/. Запросы graphify query, path, explain возвращают маленький подграф вместо сырого grep.

Когда: большой/незнакомый репозиторий, вопросы об архитектуре. После изменений — graphify update .

Serena (MCP)

Семантическая навигация по коду через LSP: найти символ, ссылки, редактировать на уровне функций — без чтения целых файлов.

Когда: типизированные языки, большие файлы, рефакторинг.

Память между сессиями (решения, баги, договорённости)

Встроенная память: CLAUDE.md

Самый простой и прозрачный вариант: текст в git, виден в review. /memory — открыть для редактирования.

Когда: всегда. Это база.

engram (MCP)

Локальная память (SQLite + поиск): Claude сохраняет решения, причины багов, конвенции и ищет их в следующих сессиях.

Когда: долгие проекты, много сессий. Минус: память личная, не в git — важное переносите в CLAUDE.md/docs.

docs/ + ADR в репозитории

Architecture Decision Records в docs/adr/, на которые ссылается CLAUDE.md через @. Общие для людей и для Claude.

Когда: командные решения, которые должны пережить людей.

Актуальная документация библиотек

Context7 (MCP)

Подтягивает свежую документацию конкретной версии библиотеки вместо «памяти» модели. Меньше выдуманных API — меньше итераций исправлений.

Когда: быстро меняющиеся фреймворки.

Пример общего .mcp.json 
{
  "mcpServers": {
    "context7": {
      "command": "npx",
      "args": ["-y", "@upstash/context7-mcp"]
    }
  }
}

Проверяйте актуальные команды установки в README каждого инструмента. Добавить сервер можно и командой claude mcp add; посмотреть состояние — /mcp.

7. Spec-driven development: Spec Kit (specify)

GitHub Spec Kit — сначала спецификация, потом план, потом задачи, потом код. Для Claude это значит: меньше угадываний, меньше переписываний и артефакты, которые можно ревьюить.

/speckit.constitutionпринципы проекта (качество, тесты, стек)
/speckit.specifyЧТО и ЗАЧЕМ — без технологий
/speckit.clarifyзакрыть неоднозначности
/speckit.planКАК — стек, архитектура, контракты
/speckit.tasksразбивка на задачи
/speckit.implementреализация по задачам
specify init . --ai claude   # инициализировать в существующем репо
specify check                # проверить окружение

Названия команд зависят от версии Spec Kit — смотрите, что создалось в .claude/commands/.

Советы

  • Ревьюйте spec.md и plan.md в PR до реализации — это самое дешёвое место найти ошибку.
  • Не используйте для мелких фиксов — overhead больше пользы.
  • Между этапами делайте /clear: артефакты лежат в файлах, контекст можно не тянуть.

Альтернативы / дополнения

  • Plan mode (Shift+Tab) — встроенный «лёгкий» вариант: Claude исследует и предлагает план, ничего не меняя.
  • Superpowers (plugin) — набор skills для дисциплины: brainstorming → plan → TDD → review.

8. Рабочий цикл задачи

  1. Исследовать. «Прочитай модуль X и объясни, как работает Y. Код не меняй.»
  2. Спланировать. Plan mode или Spec Kit. Проверить план глазами.
  3. Сначала тесты. «Напиши тест, воспроизводящий баг. Убедись, что он падает.»
  4. Реализовать маленькими шагами, каждый шаг проверяется тестом / линтером.
  5. Проверить. Попросите запустить тесты, линт, типы. Для UI — скриншот.
  6. Review. /review или отдельный subagent-ревьюер, потом человек.
  7. Зафиксировать знания. Новая конвенция → CLAUDE.md. Решение → ADR.

💡 Дайте Claude способ проверить себя (тесты, линтер, скриншот) — это сильнее всего повышает качество результата.

9. Skills, subagents, hooks, MCP — что когда

МеханизмДля чегоПример
Slash command
.claude/commands/*.md		Повторяющийся промпт, который запускает человек/review-pr 123, /fix-issue
Skill
.claude/skills/*/SKILL.md		Инструкции + скрипты, которые Claude подгружает сам, когда задача подходит. В контексте только короткое описание, пока skill не нужен.«как делать релиз», «как писать миграцию»
Subagent
.claude/agents/*.md		Отдельный контекст для изолированной задачи; возвращает только результатcode-reviewer, test-writer, исследователь репо
Hook
settings.json		Детерминированные действия на события — выполняет harness, а не модельформатировать после Edit, блокировать запись в .env
MCP
.mcp.json		Доступ к внешним системам и даннымJira/Linear, БД, документация, браузер
Пример hook: автоформатирование после редактирования 
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          { "type": "command", "command": "npx prettier --write \"$CLAUDE_PROJECT_DIR\" --log-level silent || true" }
        ]
      }
    ]
  }
}

Правило: если что-то должно происходить всегда — это hook, а не просьба в CLAUDE.md.

Пример subagent: .claude/agents/code-reviewer.md 
---
name: code-reviewer
description: Reviews the current diff for bugs, security and convention violations. Use after implementing a change.
tools: Read, Grep, Glob, Bash
---
You are a strict reviewer. Run `git diff`, read CLAUDE.md conventions,
report only real issues with file:line and a concrete fix. No style nitpicks.

10. Лучшие практики

Промпты

  • Конкретика: файл, функция, ожидаемое поведение, критерий «готово».
  • Говорите, чего не делать: «не меняй публичный API».
  • Скриншоты, логи ошибок, примеры вход/выход — вставляйте прямо в чат.
  • Для сложного — попросите сначала план, потом код.
  • Останавливайте рано: Esc — прервать, EscEsc / /rewind — откатиться.

Git

  • Отдельная ветка на задачу; частые маленькие коммиты — легко откатить.
  • Параллельные задачи — через git worktree, по сессии Claude на каждый.
  • Не разрешайте git push без подтверждения.

Качество и безопасность

  • Код от Claude проходит тот же review, что и код человека. Автор PR отвечает за него.
  • Секреты — в deny, никогда в CLAUDE.md или .mcp.json.
  • Доверяйте MCP-серверам и plugins только из проверенных источников — они выполняют код на вашей машине.
  • Проверяйте «уверенные» утверждения об API — тестами или через Context7.

Команда

  • Делитесь удачными промптами как slash-командами в репо.
  • Раз в спринт — 15 мин «что сработало / что нет с Claude» → обновить CLAUDE.md и это руководство.
  • Автоматизация в CI: claude -p "…" (headless) или GitHub Action для review PR.

13. Автонастройка (setup-kit)

Всё из этого гайда можно применить одной командой. Скрипт ничего не перезаписывает: существующие файлы пропускает, JSON сливает, перед изменением делает .bak.

# macOS / Linux
./setup-kit/setup.sh --dry-run            # что будет изменено
./setup-kit/setup.sh --preset minimal     # база: CLAUDE.md, разрешения, context7
./setup-kit/setup.sh --preset full        # + agents, hooks, ADR, Serena, graphify, Spec Kit, engram
./setup-kit/setup.sh doctor               # проверка

# Windows (PowerShell, в т.ч. RDP)
powershell -ExecutionPolicy Bypass -File .\setup-kit\setup.ps1 --preset minimal
ФлагЧто делает
--user / --project <path>только машина разработчика / только репозиторий
--with a,b / --without c,dдобавить / убрать компоненты
--yesбез вопросов (для массового развёртывания)
--dry-runпоказать diff, ничего не менять

💡 После запуска: claude → /login → /status → /mcp, затем закоммитьте CLAUDE.md, .claude/, .mcp.json. Отредактируйте каркас CLAUDE.md под ваш проект.

Полный список компонентов — в setup-kit/README.md.

Руководство живое: предлагайте изменения через PR. Проверяйте детали в официальной документации Claude Code — продукт быстро обновляется.
